Enterprise NOC — Architecture dossier

The snapshot identifies 10 computers, plus Cisco router/switch infrastructure:

  • • IT / NOC: 2 computers (1 Debian 13 host, 1 Windows workstation).
  • • Accounting: 3 Windows workstations.
  • • Finance: 2 Windows workstations.
  • • Sales: 2 Windows workstations.
  • • VoIP / authentication: 1 separate Linux server.
  • • Network: Cisco Catalyst C8200L router and C9200L switch.

The internal proxy and DNS names are part of the laboratory. They are not publicly accessible through GitHub Pages.

  • • Nginx → internal application routing (lab only).
  • • Zabbix + MariaDB → monitoring backend and web UI.
  • • Grafana → monitoring dashboards.
  • • Uptime Kuma → availability checks.
  • • Pi-hole → DNS-related services.
  • • Portainer → Docker management.
  • • Apache (site-estatico) → original internal portal.

What the evidence does NOT prove:

  • • No validated 99.9% SLA or continuous uptime claim.
  • • Some Zabbix hosts had outdated IP records; 113 items were reported as unsupported.
  • • Complete reachability between VLANs and all Docker stacks was not established.
  • • Recovery procedures were not validated as a successful full restore.
  • • Some workstation hardware details remain unknown.
